3

Existing hosts

The script connects with SSH from the control VM, checks the hardware and installs. It does not create or delete machines.

The hosts need Ubuntu 22.04 or 24.04 (x86_64), passwordless sudo for the SSH user and one empty disk per data directory. The script checks all of it first, shows the plan, and asks in the terminal before it reboots the hosts or changes their firewall and disks. A passphrase-protected key must be loaded in ssh-agent (ssh-add).

Only the path goes into the file, never the key itself.

Data disks per host

Use the stable /dev/disk/by-id/… path of each disk. List them on a host with ls -l /dev/disk/by-id/. Empty cells are asked by the script, which then offers only unused disks that are large enough. Three nodes: node 0 needs the objects disk, node 1 the data, metrics and analytics disks, node 2 none.

4

VM names and size

Lowercase letters, digits and hyphens. Put your name in it so the lab is easy to find and clean up.

Machine size

Three-node uses a fixed size: 3 × n2-standard-16 (16 vCPU / 64 GB each). There is nothing to choose here.

Advanced (optional)

How long stanctl up waits for Instana to come up: whole minutes 30–600, or 90m, 2h, 1h30m. stanctl stops waiting after this time even if Instana is still starting; larger machines and newer backends may need longer. After a timeout the installer checks the cluster anyway. Empty = 90 minutes.

Keys and admin password

From your IBM entitlement: download key, agent key, sales key, then the password for the Instana admin user.

Keys in the file are plain text. The script sets the file to owner-only (600) and offers to blank them after the install starts. Don't email or commit this file.
